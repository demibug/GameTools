圣殿＋光辉荣耀＋征伐＋远征打击（自动十字军），没有处决宣判。灰烬觉醒自动触发复仇之怒，神圣之锤由圣洁鸣钟触发；两者都不需要额外按键。征伐（1253598）是强化复仇之怒的被动天赋；光辉荣耀构筑应观察灰烬触发的复仇之怒增益（454351），“翅膀”仅为俗称。程序不按主动十字军打击，不加入任何套装交替终结技规则。

编号核对（2026-10-21）：光辉荣耀天赋为458359，其被动替换技能为462048；462048的法术条目没有限时增益描述。当前法术数据及SimulationCraft的光辉荣耀分支使用454351作为复仇之怒增益，基础持续8秒；31884用于非光辉荣耀分支。此前将本构筑观察点写成31884有误。此处为数据核对，尚未通过当前游戏客户端实际增益采样验证。参考：[SimulationCraft圣骑士实现](https://github.com/simulationcraft/simc/blob/midnight/engine/class_modules/paladin/sc_paladin.cpp)、[光辉荣耀462048](https://www.wowhead.com/cn/spell=462048)、[复仇之怒454351](https://www.wowhead.com/cn/spell=454351)。

程序根据实时已学天赋选择分支：圣殿、远征打击、光辉荣耀已学且处决未学时使用新循环。天赋来源未知时等待；光辉荣耀＋处决组合不在本次支持范围。旧的非光辉荣耀构筑保留军官请求逻辑。

## 启动

1. 在游戏中 `/reload`，重启 `bin/Release/net9.0-windows/RotationUS.exe`，先保持执行关闭。
2. 保留现有布局和 `profiles/cjq.json`；需要重新定位时，游戏 `/hiji locate on`，工具进行定位测试，通过203/203后 `/hiji locate off`，工具退出定位测试。
3. 确认圣骑士·惩戒、正常心跳、惩戒协议v5，以及B11光辉荣耀已学、B9处决未学。
4. 按下表的实际光环ID配置六个固定点。圣光裁决（免费机会）、复仇之怒、公允裁定必须按新GCD阈值重新取色保存；程序识别到光辉荣耀时自动隐藏处决行并跳过采集。已有坐标不会因改名自动指向正确光环，需核对显示源，尤其是战争艺术与复仇之怒。
5. 确认键位与替换按钮后，用“开启执行”或中键启停。窗口失焦、心跳失效、专精切换停止伤害发键；手动输入让出500ms。

## 六个输出观察点

固定点必须位置不变，消失时为纯黑，存在时非黑；需要临期判断的显示必须能在指定条件下变成不同颜色。工具只比较RGB，不读取图标上的剩余时间数字，也不创建游戏内增益显示。

| 正确光环名称 | 实际光环ID | 对应天赋ID（不作光环取点） | 单位与判断条件 |
| --- | --- | --- | --- |
| 战争艺术 | **406086** | 406064 | 自身增益；参考色表示两层 |
| 苍穹之遗 | **387178** | 387170 | 自身增益；非黑表示存在 |
| 圣光裁决（免费大锤机会） | **433732** | 425518 | 自身增益；参考色表示剩余≤2GCD；触发看B7 |
| 公允裁定 | **432629** | 432626 | 自身急速增益；参考色表示剩余≤1.5GCD |
| 复仇之怒（光辉荣耀触发） | **454351** | 458359 | 自身增益；参考色表示剩余≤2GCD |
| 异端逐除 | **383346** | 383344 | 当前目标上自己施加的减益；非黑表示存在 |

灰烬触发的复仇之怒基础持续8秒，公允裁定基础持续6秒；实际判断仍使用显示源的实时剩余时间，不能用这些基础时长倒推施法成功。圣光裁决433674是叠层，433732才是免费机会；429826是免费圣光之锤按钮；神圣意志223819不属于这个观察点。异端逐除383346是目标减益，神圣烈焰406545是用于判断灰烬前准备的另一个天赋。

游戏内 `/hiji ret auras` 会输出同一套身份清单，并向客户端查询这些ID的本地化名称。它不扫描当前增益，不证明增益正在生效，也不读取受限的剩余时间。RotationUS配置行显示名称与光环ID，悬停名称/取点按钮或进入取点窗口可查看天赋ID、单位与用途。旧构筑复仇之怒行自动显示31884。

核对依据：当前中文法术提示与SimulationCraft的光环构造代码交叉比对：[通用/圣殿光环与光辉荣耀分支](https://github.com/simulationcraft/simc/blob/3a24b834c907948dadbfab4e3a9883e4d767512a/engine/class_modules/paladin/sc_paladin.cpp)、[战争艺术、苍穹之遗、异端逐除](https://github.com/simulationcraft/simc/blob/e9a81d3415d317e1fadb961dfdcb0decd34c525f/engine/class_modules/paladin/sc_paladin_retribution.cpp)。本次完成静态身份核对；没有声称已在当前客户端战斗中逐一验证光环可读性。

GCD指当前急速下的完整公共冷却时长，不是正在倒数的GCD剩余时间。动态阈值由固定显示源表达；不能仅将旧的“≤3秒”颜色重新保存而不修改显示条件。

三项新临期配置以 `Comparison=ret-gcd` 保存。旧配置保留坐标和存在状态，但在新循环中不把旧秒数色或公允裁定存在色当成GCD临期色；条件需要该状态时诊断明确提示重配。黑色仍表示已消失。未配置的未知状态不会被猜成增益不存在。某项未学且不参与当前决策时不要求其配置。

新构筑的设置和诊断表自动隐藏“处决宣判”，决策采样与增益日志均跳过该点；切回旧构筑时恢复。原配置和字段编号保留，避免错位。

新构筑免费大锤是否触发只使用插件B7（实际免费替换形态），不再用固定点重复判断。B7为否时，免费大锤点未配置或残留颜色都不会阻塞普通大锤；B7为是时，该点仅提供临期状态。此时若点为黑色、未配置或旧阈值，则临期未知，等待有效颜色，不据此否定免费触发。剩余时间仍需外部显示提供。原 `ret_wings` 配置键保留，需核对所选点确实显示复仇之怒增益。

插件的已学判断使用表中的天赋ID，固定点按实际光环ID设置；两类编号不可互换。RotationUS仍通过像素观察，不能仅凭颜色核实图标身份。

## 光辉荣耀输出优先级

每轮重新采样，只发送一个满足条件的动作；不按固定宏序列或固定30秒计时。

1. 免费大锤实际可施放且剩余≤2GCD，优先消耗。
2. 5圣能且灰烬基础技能自身冷却中，先进入下述消耗列表。B43独立观察基础灰烬冷却，不把按钮替换、技能不可用或GCD误当作灰烬自身冷却。
3. 灰烬觉醒可施放则自动触发复仇之怒。点了神圣烈焰且目标缺少异端逐除时先尝试一次公正之剑；发键不等于施法成功，以公正之剑进入冷却或最长2秒结束准备。未配置减益点最多等2秒，不能永久卡循环；换目标、脱战或停机清除准备。
4. 圣洁鸣钟。
5. 战争艺术两层时的公正之剑。
6. 进入消耗列表。
7. 公正之剑。
8. 审判／替换后的愤怒之锤。

消耗列表：普通圣光之锤 → 满足条件的免费圣光之锤 → 最终审判／神圣风暴。免费锤在复仇之怒剩余≤2GCD，或公允裁定剩余≤1.5GCD／已经消失时释放。新构筑不等待主动翅膀冷却，也不等待或检查处决减益。大锤必须确认实际替换了灰烬按钮，且自身就绪、可用、资源和范围全部通过。

单体最终审判；10码内至少两个存活、敌对、已战斗敌人时神圣风暴；有苍穹之遗时群体也改最终审判。满圣能与普通消耗共享该规则。不硬性要求终结技先攒到3圣能，神圣意志免费技能以实际可用性和资源不足返回值判断。

典型起手：公正之剑 → 灰烬 → 满圣能时普通大锤 → 鸣钟 → 按条件循环。资源不足时继续产能，不能照此机械连按。

## 自救、打断与安全门槛

读条/引导保护：F4必须明确为“未读条/引导”，才允许输出、自疗、防御和清标记按键。治疗石、治疗药水、责难是明确保留的例外，读条、引导或施法状态未知时仍可按原条件使用：治疗石/药水要求血量≤40%且物品可用；责难要求食物标记、有效敌对目标正在施法、技能就绪可用且在射程内；三者仍要求存活、战斗且未骑乘。读条结束后按新采样恢复正常优先级。插件收到玩家读条/引导开始事件立即关闭F4，降低等待常规100ms采样的延迟；恢复空闲须由下一次完整采样确认。此保护不能撤回已发出的按键，也不阻止用户手动操作。

自救保留≤40%治疗石／药水，随后<60%圣佑术，再<80%瞬发圣光闪现→明确不可用时荣耀圣令。空敌对目标也能自救，不依赖输出增益点。闪现只在实际施法时间公开且为零时使用；不打断读条或引导。圣佑术和物品不等GCD，治疗技能要等GCD。

食物标记仍请求责难，责难键必须放真正的责难宏，不能放请求宏。请求键放自己习惯的空闲位置：

```text
/run for i=1,C_Minimap.GetNumTrackingTypes() do local t=C_Minimap.GetTrackingInfo(i);if t and t.name=="餐饮供应商" then C_Minimap.SetTracking(i,true);break end end
```

清食物（`Shift+-`）：

```text
/run for i=1,C_Minimap.GetNumTrackingTypes() do local t=C_Minimap.GetTrackingInfo(i);if t and t.name=="餐饮供应商" then C_Minimap.SetTracking(i,false);break end end
```

光辉荣耀分支忽略军官标记，不要求先开启或清除军官。所有伤害仍受有效目标、存活、战斗、未骑乘、未读条／引导、GCD、技能可用性和独立资源判断约束。伤害沿用制裁之锤（853）10码范围探测；只查询距离，不施放制裁之锤。责难使用自身射程。

姓名板扫描nameplate1～40，只有确认符合条件的单位计数；已确认至少两个则群体，否则有不确定单位时目标数未知。当前动作必需的未知状态等待，不把秘密值在Lua中比较或运算。

## 旧构筑兼容

非光辉荣耀的圣殿＋远征打击构筑保留原军官流程：准备公正之剑 → 主动翅膀 → 处决 → 清军官。`[` 放原生翅膀按钮，`]` 放 `/cast [@target,harm,nodead] 处决宣判`。旧处决点仍使用≤3秒色；原有秒数配置仍可供旧分支使用。

旧构筑爆发请求：

```text
/run for i=1,C_Minimap.GetNumTrackingTypes() do local t=C_Minimap.GetTrackingInfo(i);if t and t.name=="战场军官" then C_Minimap.SetTracking(i,true);break end end
```

清军官（`Shift+0`，仅旧构筑）：

```text
/run for i=1,C_Minimap.GetNumTrackingTypes() do local t=C_Minimap.GetTrackingInfo(i);if t and t.name=="战场军官" then C_Minimap.SetTracking(i,false);break end end
```

## 诊断与验证

协议签名F19为RGB(70,5,2)。新程序拒绝v4及更旧采样；插件和程序须一起更新。日志自动写入 `captures/ret-combat-*.log.txt`，包含B43基础灰烬冷却和本轮执行判断，发键记录不代表成功施法。

离线命令：

```powershell
dotnet build -c Release
dotnet bin/Release/net9.0-windows/RotationUS.dll --self-test
dotnet bin/Release/net9.0-windows/RotationUS.dll --ui-ret-smoke "$env:TEMP/ret-radiant-ui.png"
uv run --with lupa python Diagnostics/verify_retribution.py 'E:/Game/World of Warcraft/_retail_/Interface/AddOns/HijiAddon'
```

离线测试使用合成像素和模拟API，不发送游戏按键。游戏内还需确认：普通／免费大锤和愤怒之锤的实际按钮替换；灰烬变成大锤时B43仍反映基础灰烬冷却；三项GCD临期色与实际增益对应；单体／两目标、苍穹之遗、神圣意志、断线／失焦／切目标和食物责难。
