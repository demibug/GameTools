# 武器战士配置与验证

适用于本次用户提供的杀戮者武器战天赋。插件负责状态采集，外部工具按已确认的单体、单体斩杀、多目标优先级选择一个动作；下一次采样从头判断。沿用防战、狂暴的两行50点、进度条、心跳、前台检查和手动按键让出。

## 启动

1. 游戏输入 `/reload` 加载修改后的插件，启动 `bin/Release/net9.0-windows/RotationUS.exe`。首次使用保持执行关闭。
2. 游戏输入 `/hiji locate on`，外部选择游戏窗口并点击“定位测试”，通过后游戏输入 `/hiji locate off`，外部退出定位测试，核对当前职业为“战士 · 武器”和动态心跳。原有定位配置可载入，但尺寸或缩放改变后必须重新定位。
3. 在七行设置中分别“取点 / 取色”，采集指定状态的颜色，再点击本行“保存”。修改一行不清除其他行的待保存选择。
4. 在表格检查每项存在、消失、参考色及其他非黑颜色的解码结果。全部核对后，用“开启执行”或中键开启。工具不会创建或移动你的光环显示。

配置保存到程序目录 `profiles/wqz.json`，与 `fz.json`、`kbz.json` 独立。没有预填真实武器点位。未配置、停用或采集失败为未知，可能阻塞依赖该状态的输出；不能把未知当光环缺失。

## 七个特殊点

| 点位 | 取参考色时的状态 | 黑色 | 精确匹配参考RGB | 其他非黑颜色 |
| --- | --- | --- | --- | --- |
| 撕裂不足10秒 | 当前目标上的自身撕裂不足10秒 | 缺失 | 不足10秒 | 未进入不足10秒状态 |
| 撕裂不足5秒 | 当前目标上的自身撕裂不足5秒 | 缺失 | 不足5秒 | 未进入不足5秒状态 |
| 巨人打击 | 当前目标上的自身巨人打击存在 | 缺失 | 存在 | 存在 |
| 猝死两层 | 猝死两层 | 缺失 | 两层 | 一层 |
| 殒命在即三层 | 殒命在即三层 | 缺失，按零层处理 | 三层 | 不足三层 |
| 刽子手的精准两层 | 刽子手的精准两层 | 缺失，按零层处理 | 两层 | 不足两层 |
| 间接伤害三层 | 间接伤害三层 | 缺失，按零层处理 | 三层 | 不足三层 |

巨人打击保存参考色但只判断黑/非黑。其他六点需非黑参考色，精确比较RGB，不使用容差、数字识别或施法次数猜层数。两个撕裂点独立保存，可使用相同参考色。点位固定、消失后露出纯黑、其他图标不能补位；取点避开动画、数字边缘和冷却扫光。目标减益必须跟随当前目标更新，且只显示自身施加的效果。

## 按键与阶段

| 动作 | 按键 |
| --- | --- |
| 剑在人在 | `8`，10码综合条件、血量严格低于50%、技能就绪且可用 |
| 天神下凡 | `9`，仅军官标记请求时释放 |
| 剑刃风暴 | `[` |
| 巨人打击 | `]` |
| 横扫攻击 | `\` |
| 压制 | `;` |
| 致死打击 | `'` |
| 顺劈斩 | `.` |
| 猛击／英勇打击 | `Shift+[` |
| 斩杀 | `Shift+]` |
| 英勇投掷 | `Shift+;` |
| 胜利在望／乘胜追击 | `7`，继承狂暴：5码条件、血量<75%、技能就绪可用、GCD就绪 |
| 拳击 | `0`，继承狂暴的食物标记请求 |
| 袋里乾坤 | `Shift+.`，继承狂暴：战斗、15码条件、血量<80%、就绪且GCD就绪 |
| 治疗石／治疗药水 | `-`／`=`，沿用血量≤40% |
| 碎裂投掷 | `Shift+\`，继承狂暴：15码条件、目标有吸收、就绪且GCD就绪 |
| 取消军官／食物标记 | `Shift+0`／`Shift+-` |

通用顺序为剑在人在→胜利在望／乘胜追击→袋里乾坤→治疗石→药水→食物标记清理／拳击→军官标记清理／天神请求→碎裂投掷→输出列表。通用技能独立于未配置的输出光环，不需要新增特殊点位。

与狂暴一致，从小地图追踪项读取“餐饮供应商”与“战场军官”请求。食物标记开启、战斗近战条件成立、目标正在施法／引导且拳击就绪时发拳击；脱战、目标停止读条、拳击冷却或离开近战时取消食物标记。拳击不等待GCD。军官标记请求天神，脱战或确认天神进入自身冷却后取消军官；武器没有鲁莽，不发送鲁莽。碎裂投掷已按本次继承要求启用狂暴的 `Shift+\`。

打断不生效时检查44食物标记、45目标施法/引导、46拳击就绪及3近战条件。开启执行需要50“武器通用字段已加载”为是；未更新或未重载到新采集代码时明确提示 `/reload`，不把新增字段的黑色当成有效技能状态。

附近有效敌人估算≥2使用多目标列表。单目标且目标血量低于35%使用单体斩杀列表，猝死不改变阶段。血量35%和剑在人在50%的条件由插件阶梯曲线显示；怒气>40用原始怒气阈值条。压制沿用两格进度条，区分至少一充能、两充能，来源失败不会保留旧充能。

英勇打击是猛击的替换形态，共用猛击按钮和按键；单体识别到替换后提前使用，普通猛击保留兜底。多目标按用户列表在末位使用猛击技能族。天神已从三套输出列表移除，仅在军官标记开启、近战且技能可用就绪时释放；标记关闭或未知均不自动发9。

## 已确认的输出顺序

单体：顺劈斩（撕裂缺失或不足10秒，巨人打击就绪）→巨人打击→斩杀（猝死两层）→斩杀（剑刃风暴已就绪、巨人打击存在、殒命在即不足三层且猝死存在）→剑刃风暴（巨人打击期间）→英勇打击→致死打击→斩杀（猝死存在）→压制→顺劈斩（撕裂缺失或不足5秒）→猛击。

单体斩杀：巨人打击→英勇打击→剑刃风暴（巨人打击期间）→致死打击（刽子手的精准两层）→斩杀（猝死或怒气>40）→压制→斩杀。

多目标：横扫攻击→顺劈斩（补缺失撕裂）→巨人打击→顺劈斩（间接伤害三层）→剑刃风暴→斩杀（猝死两层）→顺劈斩→压制（两充能）→斩杀（猝死存在）→压制→斩杀→致死打击→猛击。多目标剑刃风暴没有额外巨人打击限制。

## 游戏内核对

合成验证不能替代实际游戏。配置七点后逐项核对黑色、参考色、其他非黑；确认技能可用/就绪、压制0/1/2充能、猛击变英勇打击、目标低于35%分支、怒气40/41边界及玩家低于50%的剑在人在。还需核对胜利在望／乘胜追击、袋里乾坤、治疗石药水，以及食物标记拳击和军官标记请求。切换目标检查撕裂/巨人打击即时变化；在木桩和副本分别核对接口受限情况。出现“等待状态”可从诊断表和保存截图与日志定位所缺字段。

## 开发验证

项目目标仍为.NET 9。当前机器默认.NET 10 SDK会要求未安装的9.0.19目标包；本次用已安装的9.0.312 SDK和9.0.14目标包构建，不改变项目目标框架。验证入口为 `--self-test`、`--ui-arms-smoke <图片路径>`，以及 `uv run --with lupa python Diagnostics/verify_arms.py <插件目录>`。自检和界面合成验证不发送游戏按键。
