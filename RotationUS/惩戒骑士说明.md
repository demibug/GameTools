# 惩戒骑士配置与验证

针对本次攻略天赋的圣殿／自动十字军构筑，暂不考虑套装。Lua采集状态，外部工具每次选择一个动作。翅膀＋处决由军官标记请求；灰烬、鸣钟自动；圣光之锤根据常规／免费机会自动释放。60秒／30秒是规划节奏，程序使用实际冷却而不按固定计时强行施放。

## 启动与取点

1. 更新插件后在游戏执行 `/reload`，启动 `bin/Release/net9.0-windows/RotationUS.exe`，先保持执行关闭。
2. 游戏 `/hiji locate on`，工具选择游戏窗口、点击“定位测试”；通过203/203后游戏 `/hiji locate off`，工具退出定位测试，确认“圣骑士 · 惩戒”和正常心跳。
3. 按下面的七点表配置固定光环显示，逐行取点／取色并保存，核对诊断表中消失、存在及条件色。程序不创建光环显示；位置不能随图标补位移动，消失背景必须纯黑。
4. 按键绑定和两种圣光之锤形态手动验证通过后，用“开启执行”或中键启停。窗口失焦、失去心跳、专精切换均停止发伤害键；手动按键让出500ms。

配置独立保存为程序目录 `profiles/cjq.json`，不会借用奶骑／武器点位。未配置为未知，相关优先级会显示等待原因；窗口或布局变化后重新取点。执行关闭时仍可查看当前候选和阻挡原因。

比较精确RGB。指定色表示对应层数／临期条件，不能对着始终同色的图标采样来区分时间。目标减益必须跟随当前目标更新；层数和剩余时间由你配置的固定显示提供，不读取图标数字或猜测。未学苍穹之遗、战争艺术、圣光裁决时，对应判断按真实已学状态跳过。

名称对照（2026-10-16核对）：

- 苍穹之遗（Empyrean Legacy）：自身增益，光环387178、天赋387170；下一个伤害型单体圣能技能附带神圣风暴，所以程序在多目标时也会选择最终审判。旧标签“天穹之遗”是误写。
- 圣光裁决（免费大锤）：Light's Deliverance的免费施放光环433732，来源天赋425518；取的是已获得免费施放机会及其剩余时间，不是同名叠层433674，也不是神圣意志（Divine Purpose，增益223819）。433732标记为No Aura Icon，默认BUFF栏可能不显示；取色前需确认当前客户端有对应的固定显示，不能按同名叠层图标取点。
- 公允裁定（Undisputed Ruling）：自身增益432629，施放大锤后获得的短时急速增益；旧标签“无可争议的统治”不是对应的简体中文技能名。
- 处决宣判（Execution Sentence）：当前敌人身上由自己施加的处决减益，观察有无和剩余≤3秒；不是技能冷却，也不是自己身上的增益。施法技能343527与目标光环可能不是同一ID，需按当前客户端实际目标减益配置。
- 异端逐除（Expurgation）：公正之剑施加的目标持续伤害，减益383346；旧标签“当前目标灼烧”只是效果描述。只观察当前目标上由自己施加的效果是否存在。

这些特殊点只读取你配置的位置颜色，程序不会自动核实图标身份。名称修正保留原配置键和坐标；之前选错图标的项需要重新取点。

### 标记宏

“爆发请求”和“打断请求”放到你自己习惯的手动键；不要覆盖上表的程序键。“责难”格必须放真正的责难宏，不能放只开启食物标记的请求宏。

爆发请求（开启军官）：

```text
/run for i=1,C_Minimap.GetNumTrackingTypes() do local t=C_Minimap.GetTrackingInfo(i);if t and t.name=="战场军官" then C_Minimap.SetTracking(i,true);break end end
```

打断请求（开启食物）：

```text
/run for i=1,C_Minimap.GetNumTrackingTypes() do local t=C_Minimap.GetTrackingInfo(i);if t and t.name=="餐饮供应商" then C_Minimap.SetTracking(i,true);break end end
```

清军官（`Shift+0`）：

```text
/run for i=1,C_Minimap.GetNumTrackingTypes() do local t=C_Minimap.GetTrackingInfo(i);if t and t.name=="战场军官" then C_Minimap.SetTracking(i,false);break end end
```

清食物（`Shift+-`）：

```text
/run for i=1,C_Minimap.GetNumTrackingTypes() do local t=C_Minimap.GetTrackingInfo(i);if t and t.name=="餐饮供应商" then C_Minimap.SetTracking(i,false);break end end
```

## 标记与输出规则

沿用武器战的小地图追踪“战场军官”与“餐饮供应商”开关。Shift+0、Shift+-沿用现有清除相应追踪的宏，确认宏只负责清标记，不施放技能。开启执行前的旧军官请求会先清除；请在执行已开启后重新请求爆发。

军官请求到达时，已学的翅膀／处决须都自身就绪；否则清理请求。神圣烈焰已学且目标没有异端逐除时，优先尝试一次公正之剑作为准备；观察到公正之剑进入自身冷却就继续，减益取色不再是开翅膀的硬门槛。公正之剑明确不可用时跳过准备；准备状态未知或发键后未确认，整个准备阶段最多等2秒再跳过，不把跳过视为施法成功或减益已存在。随后翅膀→处决，各自进入真实自身CD才确认；两项完成后清理军官。翅膀／处决发键后2秒未确认或整组超过8秒会取消。手动关标记、换目标、失去目标、脱战、停机、切窗口、心跳失效都会撤销旧请求。

食物请求：沿用防战／武器战的目标施法判断，目标正在读条／引导且责难就绪可用、在自身射程内时Shift+3；这些条件明确不满足就清理食物，未知则等待。不再要求“目标可打断”为真，因此不可打断读条也会尝试，是否打断成功由游戏决定。责难和自救物品不等伤害GCD。物品在战斗、存活未骑乘且血量≤40%时按治疗石→治疗药水选择，可在空目标时自救。自身血量<60%且技能就绪可用时先圣佑术（9）；血量<80%先瞬发圣光闪现（7），明确不可用时再荣耀圣令（8）。两种治疗都需GCD就绪且未读条，圣佑术不等GCD。普通读条闪现不自动使用。等于60%／80%不触发对应阈值。其他辅助、防御、祝福只留手动键位。

责难的字段13“目标可打断”仅作诊断，不参与释放或清理标记；无论真、假、未知或缺失，都不会阻塞责难。采集仍通过C_CurveUtil.EvaluateColorFromBoolean原生显示受限布尔值：不可打断为黑，可打断为白；缺失、类型错误或接口失败为未知。请求仍需要开启餐饮供应商标记；诊断分别显示目标、施法、责难冷却、可用性、射程的阻塞原因。责难仍查自身射程，不受输出技能10码或群体数量限制。

2026-10-17低圣能误按终结技修复：普通布尔采集只接收接口的第一个返回值。C_Spell.IsSpellUsable的第二个返回值是insufficientPower，不能传成颜色反转参数；否则“不可用＋资源不足”会错误显示为可用，导致1圣能反复按最终审判／神圣风暴。修复后资源不足显示不可用，仍保留真实免费施法时低圣能可用的情况，不硬加3圣能限制。此项插件修复执行 `/reload` 即可生效。

同类问题复查：普通与反转布尔显示拆为两个独立入口，避免接口额外返回值选择反转。共用修复覆盖翅膀／征伐、处决、普通／免费大锤、最终审判、神圣风暴、灰烬、鸣钟、公正之剑、审判／愤怒之锤和责难；荣耀圣令、圣光闪现、圣佑术的独立采集入口也通过验证。回归覆盖18条技能／替换形态路径、180种可用状态组合，以及独立冷却失败和恢复；包括资源不足、其他不可用原因、真实可用、受限布尔、缺失与错误。三种自救的原采集已只接收首个返回值，不存在原先的反转缺陷。手动技能无自动可用性分支。

当前低圣能排查版本为协议v4：IsSpellUsable一次调用的两个返回值分别采集，原可用字段保留第一项，B30～B39记录十个输出／打断技能“未报告资源不足”，B40～B42依次记录荣耀圣令、圣光闪现、圣佑术。所有自动技能还必须确认第二项没有报告资源不足；资源不足或该项未知均不放行。免费消耗不另加固定圣能门槛。v3数据会被拒绝，需要同时重载插件并重启更新后的工具。回归覆盖18条路径、198种双返回值组合，包括“可用为真但资源不足为真”的冲突情况；真实客户端是否出现该组合，需用新的连续日志确认。

惩戒连续日志自动写入程序目录captures/ret-combat-*.log.txt，在浮窗／最小化期间仍独立记录状态变化，不再依赖主表格刷新。日志包含每次记录的圣能、原始技能可用性、独立资源判定、距离、冷却、光环取色和执行判断。执行判断是按键请求而非成功施法证明；无效采样会明确标注。保存截图与日志时也会附上连续日志路径。

伤害顺序：当前授权的翅膀／处决 → 常规锤 → 符合消耗条件的免费锤 → 满圣能终结技 → 灰烬 → 鸣钟 → 战争艺术两层公正之剑 → 普通终结技 → 公正之剑 → 审判技能族。免费锤在自身临期、翅膀／处决临期，或没有公允裁定增益且不需等待当前授权翅膀时使用；无军官请求时不会永久等翅膀。

单体用最终审判；制裁之锤（853）10码范围内至少2个存活、可攻击且已进入战斗的敌人时用神圣风暴，苍穹之遗存在时改最终审判。两处分支（满圣能／普通消耗）使用同一规则。不按主动十字军打击。群体计数遍历nameplate1～40；未进入战斗、死亡、不可攻击或10码外的单位不计数，不再使用交互距离。受限、缺失或报错的状态不算已确认敌人：已确认至少2个时判群体，否则只要还有不确定单位就显示未知。这里只查询制裁之锤的距离，不要求它冷却完毕，也不会施放它。姓名板计数不等于实际命中数；已移除惩戒的物品距离回退。

2026-10-17距离限制：惩戒的审判（包括替换后的愤怒之锤）、处决宣判、圣洁鸣钟、最终审判、公正之剑、灰烬觉醒、圣光之锤（普通／免费）、神圣风暴统一使用制裁之锤（853）对当前目标的10码范围判断，替代各自原射程。目标不在范围内或范围未知时，这八项不发键；爆发前补公正之剑、爆发中的处决以及满圣能终结技同样受限。这里只查询制裁之锤的范围，不施放它，也不要求它冷却完毕或可用。此限制约束当前目标距离，不改变技能本身的范围伤害半径。插件更新后执行 `/reload`，重启RotationUS即可看到对应的10码诊断标签。

复仇之怒／征伐也要求当前有效敌对目标在制裁之锤10码内，独立采集到B28，不依赖是否学习处决宣判；首次发键和重试都检查，超距或未知就等待，沿用原爆发请求超时规则。协议升级为v3，旧插件数据不会放行；需游戏内 `/reload` 并重启RotationUS。

其余距离条件：责难使用自身技能对当前目标的范围接口；圣光闪现、荣耀圣令按自身宏，圣佑术、治疗石和治疗药水用于自身，均不检查敌人距离。手动保留的圣盾术、自身圣疗术、自由祝福、保护祝福、牺牲祝福没有程序距离判断，由游戏实际施法规则限制。清毒术没有程序逻辑。

## 游戏内待验证

版本和角色天赋按你的要求留到实测：确认已导入攻略码、圣殿与自动十字军已学、没有光辉荣耀。核对常规／免费圣光之锤替换、审判替换、实际冷却、七个固定点、技能可用／范围，以及责难请求。未知字段保持橙色；参与当前释放条件的未知状态会等待，仅诊断的“目标可打断”不阻塞。

先在关闭执行时验证采样，再用木桩核对1／2目标、圣能满值、免费消耗后的真实资源、军官成组、食物责难和物品。切目标／窗口、停止执行再恢复时确认旧爆发不会补放。保存截图与日志可定位等待的字段。
