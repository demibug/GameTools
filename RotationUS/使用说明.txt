RotationUS 职业执行与游戏点位诊断

启动
  双击 bin\Release\net9.0-windows\RotationUS.exe。
  普通启动仅显示程序窗口，不再弹出 CMD 控制台；测试命令和 --legacy 保留控制台输出。
  默认打开执行与诊断窗口，执行初始为关闭。--diagnose 也是同一模式。
  完成校准、退出定位测试后，鼠标中键或任一侧键切换开启/关闭执行。
  窗口内“开启执行（中键）”/“关闭执行（中键）”按钮也可操作，状态显示在特殊点设置旁。
  显示当前职业 / 专精，使用对应的字段、profiles 配置和现有执行代码、键位。
  仅有效职业数据、心跳正常且选中游戏处于前台时发键；切出游戏时等待。
  手动按原 skipKeys 或 Alt 后让出 500 毫秒；中键长按只切换一次。
  暂停查看、定位/校准、切换游戏窗口、保存特殊点、导出或清理文件会关闭执行，需要再次开启。
  游戏保持窗口化或无边框窗口化；诊断窗口避开游戏顶部色条。
  已接入 11 个专精：战士武器 / 狂暴 / 防护、德鲁伊野性 / 守护、死亡骑士邪恶、圣骑士防护、潜行者狂徒、武僧酒仙 / 踏风、恶魔猎手复仇。
  狂暴的取点、键位、四套优先级和字段表见同目录“狂暴战士说明.md”。
  狂暴胜利在望／乘胜追击血量条件为严格低于 85%，防战胜利在望为严格低于 70%；狂暴袋里乾坤为严格低于 80%，防战为不高于 60%。
  其他职业 / 专精显示职业名称和专精 ID，暂仅展示原始颜色，不开启执行。

职业与配置切换
  插件输出当前职业 ID 和专精 ID；外部自动识别，无需修改 Program.cs 的固定职业。
  每个专精单独保存配置：profiles/fz.json、kbz.json、wqz.json、cat.json、bear.json、udk.json、fq.json、ktz.json、jx.json、tf.json、dht.json。
  切换角色、职业或专精后，窗口自动切换字段、资源类型、配置和执行实现，并关闭执行。
  插件会清空旧色块后更新新专精，切专精无需再次 /reload；首次更新本次插件仍需 /reload。
  切换后核对职业显示与心跳，再按中键 / 侧键开启执行。当前配置文件名显示在职业旁。
  所有职业、专精、天赋共用右侧宽版黑底和标记：黑底 x=530–730、高 20，标记 x=740/750/760（游戏 UI 单位）。
  旧防战配置仍属于 profiles/fz.json；切换到统一布局后，旧特殊点停用、参考色清除，请重新截图取点和取色。
  diagnostic-layout.json 用于启动时寻找职业标记，新的特殊点只保存在所属专精配置里。

定位测试与位置校验
  1. 游戏输入 /reload，确保更新后的 HijiAddon 已载入。定位本身不限制职业。
  2. 输入 /hiji locate on。顶部显示 50 个绿/蓝/红点，第二行是紫/青交替点。
  3. 外部窗口选择正确的 Wow.exe，点击“定位测试”。工具每 0.5 秒重新寻找色块。
  4. 表格显示两行 100 个点及 3 个标记的坐标、实际 RGB、预期颜色及通过/失败。
     连续两次位置一致后保存坐标；状态应显示“定位校验通过 103/103 · 坐标已保存”。
  5. 游戏输入 /hiji locate off，外部点击“退出定位测试”，恢复实时数据。
     约 0.5 秒后显示对应职业 / 专精及“心跳正常”。
  已移除重复的自动校准和校验位置按钮，统一通过定位测试寻找、校验和保存。
  locate on/off 与原 test on/off 命令均可使用。定位坐标和各专精配置下次启动自动读取。
  只接受统一右侧 wide-v2 布局；legacy 和 wide-v1 的旧坐标不能用于执行，请 /reload 后重新定位。

分辨率与 UI 缩放变化
  定位测试期间，改变分辨率或 UI 缩放后，工具会自动寻找、校验并保存新坐标。
  实时模式发现游戏客户区尺寸变化后，停止使用旧坐标并自动进入定位测试。
  此时需要在游戏输入 /hiji locate on，显示用于寻找点位的彩色图案。
  只修改 UI 缩放、窗口尺寸保持不变时，主动点击“定位测试”。
  显示器/DPI 变化后也使用定位测试确认位置。
  普通游戏数据无法可靠区分黑色的未激活点与背景，因此重新定位依赖专用彩色图案。
  UI 缩放太小导致两行挤在同一像素时，需要适当调大 UI 缩放。
  新旧标准点位不同后，特殊点 51 会自动停用，需单独确认它的新坐标。
  狂暴的全部命名特殊点也会停用。旧布局升级时清除旧参考色，重新采集；已使用 wide-v2 且客户区、标准点保持不变的特殊点可以保留。

实际验收（防战示例；其他职业按对应字段核对）
  手动攻击木桩：核对第 1 点的战斗状态。
  接近/远离目标：核对 3–5 点；这些点同时包含战斗、坐骑、施法和目标存活条件。
  获取/消耗怒气：核对第 7 点；它显示怒气占最大怒气的比例。
  手动使用技能：核对 13–20 点冷却灰度的变化；编码比例不是剩余秒数。
  观察游戏内置技能建议：核对 21–25 点亮起的技能；有 GCD 就绪条件。
  使用盾牌格挡：核对第二行 B1/B2 及状态栏的 0/1/2 充能。
  切换小地图“战场军官”“餐饮供应商”追踪：核对 8、28 点。

窗口操作
  主界面工具栏圆形红绿按钮用于收起窗口；标题栏最小化按钮也会收起为置顶悬浮按钮。
  绿色表示循环开关已激活，红色表示已关闭。等待游戏前台、心跳或手动按键让行时仍按开关状态显示。
  左键单击悬浮按钮恢复原界面，原界面保留同款按钮；拖动悬浮按钮只移动位置，不展开。
  悬浮模式隐藏主窗口和任务栏入口，采样与循环继续；中键和侧键仍可切换执行，红绿状态即时同步。
  悬浮按钮位置保存在程序旁 floating-window.json，重启后继续使用；自动限制在可见屏幕范围内。
  悬浮按钮遮挡采样区时自动移开；关闭主界面会退出程序并移除悬浮按钮。
  执行开启时每约 30 毫秒读取一次最新像素，先判断并发键；窗口约每 250 毫秒刷新一次。
  表格、预览和诊断日志按窗口显示采样更新，短于 250 毫秒的变化可能不显示；执行仍使用每次最新采样。
  截图缓冲区会复用，预览使用同一次采样的副本，不额外截图。窗口最小化时停止界面刷新，执行继续。
  点击表格行：像素预览中以黄色方框标记该点。
  预览与表格均可滚动。未定义字段显示原始颜色，具体字段随专精切换；防战无视苦痛使用特殊点 51。
  “暂停查看”：冻结画面、字段和日志；“继续采样”恢复。
  “清空窗口日志”：清空窗口目前积累的日志，继续采样会记录新的变化。
  “清空已保存日志”：直接清空程序旁 captures 文件夹中的 *.log.txt，以及程序记录的自定义位置日志，同时清空窗口旧日志。
  不再要求选择文件夹；自定义导出的日志路径保存在 saved-log-files.json，重启后仍可直接清理。
  保留日志文件本身、截图 PNG、字段 CSV 和坐标 JSON；被占用或无写入权限的文件会报告失败。
  “保存截图与日志”：保存同名 PNG、CSV、log.txt、layout.json。
  PNG 是原始采样像素；CSV 是窗口字段；日志含采样时间与客户区截图范围。
  导出包含原始颜色，仅证明程序读到了这些颜色，需用上述游戏操作确认字段含义。
  日志保留最近 1000 条变化。
  日志宽度只测量新增行，避免满 1000 条后逐条删除时反复测量整份日志造成卡顿。

无视苦痛：特殊点 51
  已移除插件新增的 Buff 计时、字体及第 30 点输出。游戏 /reload 清除旧显示区域。
  1. 校准标准点位后，游戏 /hiji locate off，外部退出定位测试。
  2. 将冷却管理器的无视苦痛图标放在固定位置，让画面显示你希望触发施放的颜色。
  3. 点击“截图取点 / 取色”。工具关闭执行、切到所选游戏，显示客户区的静止截图。
  4. 鼠标移动查看客户区 X/Y、原始 RGB 及像素放大图。左键点击选取，或方向键微调后 Enter 选取。
     Esc / 右键取消，取消保留原配置。成功选取后显示待保存坐标和 RGB，再点击“保存特殊点”写入配置。
  5. “保存特殊点”默认禁用，截图取点取色成功后才可点击；保存成功后再次禁用。
     取消取点、手动修改坐标、切换游戏或重新定位后也会禁用，需要重新取点取色。
     防战配置保存到当前程序旁的 profiles/fz.json，包括 Special、SpecialReferenceColor、SpecialEnabled。
     重启自动读取。无需修改插件，也无需编辑代码；执行读取同一个配置。
  判断：实时 RGB 为纯黑 (0,0,0)，或者完全等于取色保存的 RGB，判定需要施放无视苦痛。
  保留原来的距离、怒气、技能优先级，以及队伍中高怒气时的独立施放条件。
  表格第 51 点显示实时坐标、RGB 和“需要施放无视苦痛：是/否”；设置栏显示取色 RGB。
  手动施放、等待 Buff 消失时核对该行，确认取到的像素能区分预期状态，再开启执行。
  需要修改坐标或启用状态时，先截图取点取色，再调整启用勾选并保存；修改坐标后须重新取色。
  无取色的旧配置仍只判断纯黑；未启用特殊点时不执行颜色触发，高怒气条件保留。
  分辨率、UI 缩放或图标位置改变后重新取点；标准点重新定位发生偏移时特殊点会停用。
  复仇恶魔猎手沿用其原代码的特殊点非黑判断，设置保存在 profiles/dht.json，与无视苦痛配置完全独立。
  狂暴使用独立命名特殊点，保存到 profiles/kbz.json；其余专精不使用特殊点，相关控件禁用。

无有效数据时
  游戏退出、最小化、诊断窗口遮挡采样区：显示未知。尺寸变化会进入定位测试。
  插件定位模式、暂无对应执行代码、心跳停更超过 1.5 秒：保留原始 RGB，解码显示未知。
  心跳在职业数据更新成功后变化；它可以发现更新停顿，不能证明每个游戏 API 值都正确。
  切专精后自动清空旧数据并更新对应实现，外部执行关闭，等待新数据心跳。
  截屏读取可受其他窗口、覆盖层、HDR/颜色处理影响；确保色条可见。

开发与验证
  dotnet build RotateUS.csproj -c Release
  bin\Release\net9.0-windows\RotationUS.exe --self-test
  性能检查（不发键）：RotationUS.exe --profile diagnostic-layout.json
  日志性能检查（不截图、不发键）：RotationUS.exe --log-profile
  uv run --with lupa python Diagnostics/verify_addon.py "D:\Game\World of Warcraft\_retail_\Interface\AddOns\HijiAddon"
  需要 .NET 9 Windows Desktop Runtime（当前电脑已具备）。

旧执行入口
  RotationUS.exe --legacy 进入原程序：当前写死防战，鼠标中键/侧键切换暂停。
  旧入口的标准点仍使用 Program.cs 固定坐标；启动时读取 profiles/fz.json 的特殊点 51 和取色 RGB，兼容旧配置迁移。
  自动职业切换使用默认窗口，--legacy 仅保留原有固定防战入口。
  修改特殊点后需重启旧入口；默认窗口保存后立即生效。
  做点位验收时使用默认窗口，并保持执行关闭。
