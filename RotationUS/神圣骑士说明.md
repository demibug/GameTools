## 掉血判定

以下是根据反应式治疗、避免过量治疗的原则制定的初始工程参数，不是社区统一规定。百分比点位只有8位红色通道，边界存在约0.4个百分点的量化误差。

| 单体血量 | 分类 | 处理 |
|---|---|---|
| <20% | 危急 | 优先可用的即时治疗；圣疗由玩家手动使用 |
| 20%～<60% | 大掉血 | 即时技能优先；无灌注、震击冷却、站定且法力足够时读条圣光术，否则闪现兜底 |
| 60%～<85% | 普通掉血 | 灌注闪、震击、荣耀圣令及必要的闪现兜底 |
| ≥85% | 轻微掉血／满血 | 不主动补单体治疗 |

小队：至少3人低于70%，或至少2人低于50%，是群体大掉血。至少2人低于85%是普通群体掉血，可以启动美德。

团队：N为血量可读的在线存活成员数。至少 max(3, ceil(N×30%)) 人低于70%，或至少 max(2, ceil(N×20%)) 人低于50%，是群体大掉血。普通群体掉血需要 max(3, ceil(N×20%)) 人低于85%。40人团的对应门槛是12／8／8人。

空位、离线、死亡／鬼魂不计入N；未知血量不当作满血或零血。可读存活成员占可读存活＋未知成员不足75%时，不依据队伍血量启动群体策略。群体判定观察整个小队或团队，不知道团队中每人的治疗距离或成员之间距离，不能保证鸣钟／美德覆盖全部受伤者。小队自动选人单独检查治疗技能距离。

阈值保存在运行程序目录的 `profiles/holy.json` 中的 `HolyThresholds`。关闭程序后修改，再启动；比例写0～1的小数。例如 `HealBelow=0.85`、`Major=0.60`、`GroupLow=0.70`、`GroupCritical=0.50`、`RaidLowFraction=0.30`、`RaidCriticalFraction=0.20`、`MinimumCoverage=0.75`、`HolyLightMana=0.30`。自身7／8／9宏与当前目标治疗共用HealBelow，默认均为低于85%；普通自疗还需不抢占更低血量的可治疗队友；自身普通闪现也使用这条治疗线并要求静止，且可通过小队选人或当前团队友方目标施放的可用震击必须先使用，不能被自身普通闪现抢占。治疗石药水仍固定40%，圣佑术固定低于50%。HolyLightMana现在控制普通读条圣光术的法力门槛，默认法力比例至少30%，同时要求技能实际可用；神性之手瞬发圣光术不要求此额外法力比例门槛，但仍要求技能可用。圣疗与自律检查已移出自动策略，交给玩家手动处理。

## 策略与选人

2026-10-12：本轮实现不增加点位的基础调整。保留原有采集协议、三个外部光环点和按键绑定；不把按键发送、技能进入冷却或短暂观察期当作技能成功／美德生效／翅膀仍在生效的证明。

动作均要求玩家存活、未骑乘且在战斗中。自身治疗宏、圣佑术、治疗石／药水不再要求当前目标存活：空目标、死目标或敌对目标不会阻挡自救。目标治疗仍要求目标存活、友方、治疗距离和血量已知。圣佑术及物品在施法／GCD等待之前判断；普通治疗仍须施法结束和GCD就绪。

小队从 player、party1～party4 中选择范围内血量最低且低于治疗线的存活成员；离线、死亡、范围未知／范围外、血量未知成员不参与。团队保留玩家当前目标，不自动选择团队成员。自己与可治疗队友使用同一套血量比较，危急时也不因为身份是玩家而抢占更低血量的可治疗队友。普通群伤符合美德条件时，先准备美德与后续治疗；当前目标可以是自己或队友，已满足条件时不额外换目标。普通自疗排在这段铺垫之后。团队中未选中的成员没有自动治疗路径，不能仅凭其血量压住当前可执行的自救。

选人只发送一个选择键，等目标身份连续两次确认后才对其施法。新的危急候选可替换旧的非紧急选人等待，仍需重新确认；两秒未确认提示检查绑定。自身宏／自保／物品不受这段等待阻挡。食物标记仅采集，不限制治疗、选人或盾击。

Critical默认20%，属于工具参数。自己或当前可治疗队友低于Critical时，按实际可用技能直接抢救：满圣能或确认免费消耗触发时先用荣耀／永恒之火；否则可先灌注闪、神性之手瞬发圣光术或震击，再考虑普通3圣能消耗。自身震击需要当前已确认选中自己，其他自身瞬发可通过7／8／9宏执行。每次请求后重新采样，回到普通群伤时重新优先判断美德。至少两名成员危急且群体采样可靠时，可以先用紧急鸣钟或附带鸣钟的光环掌握。圣疗仍手动处理。

### 圣能与鸣钟

小队鸣钟使用独立的有效群伤门槛：至少3人低于TollLow（默认80%），或至少2人低于TollCritical（默认60%）。团本保留按存活人数比例计算的大掉血门槛；至少两人危急可走紧急例外。仍要求有队伍、血量可靠、当前友方目标可治疗、技能就绪且可用。小队按0对自己鸣钟；团队按;对当前友方目标鸣钟。

非紧急鸣钟：已有至少3圣能且当前存在可治疗对象、荣耀可用时先消耗，下一次采样再判断。真正施放鸣钟要求点91确认圣能不足3，且没有5圣能信号；圣能未知、或团队选中满血对象但还有3～5圣能时，不直接鸣钟。神圣意志免费消耗按实际Buff判断，施放后重新读取圣能，不能假设免费荣耀降低了圣能。

5圣能时优先有效治疗消耗；荣耀／永恒之火不可用时，只要有真实治疗需求，仍可使用震击、确认有灌注的闪现、确认有神性之手的圣光术，或满足原条件的站定读条治疗。避免圣能溢出不能阻止加血。满圣能时仍不使用审判继续伤害产能，无治疗需求且不能盾击时等待。盾击仍要求全队在线存活成员均达到治疗线、没有未知血量、群体可靠、自己健康、当前存活敌人在确认近战范围、技能已学且就绪可用、未施法且GCD就绪；不要求震击至少两充能。3～4圣能仍不自动盾击。

奶骑近战距离只查询三个5码物品8149／136605／63427的 `C_Item.IsItemInRange(itemID,"target")`，不查询责难、十字军打击、盾击或法术书近战范围，不使用物品。先公开确认当前目标存活且可攻击；目标无效、不允许攻击或可攻击性未知时不调用物品范围接口。三个物品独立查询：任一公开true为范围内；没有true但存在公开false为范围外；全部nil、秘密值、无效返回或报错为未知。查询不以物品拥有数量为前提，但未拥有／未缓存／不适用的物品仍可能返回nil；此时不猜测范围。每次神圣采样重新查询（正常约0.1秒），换目标后的首个采样清除旧证据。仅针对当前敌人，不自动切敌人或使用targettarget；距离不代表盾击锥形命中，面向、视线和免疫情况需玩家处理。Shift+.绑定 `/cast [@target,harm,nodead] 正义盾击`。

点14／15／18分别记录上述三个物品的原始查询分类：绿=范围内，红=范围外，橙=nil或无效返回，紫=秘密值，品红=报错，蓝=未查询（目标无效或可攻击性未知），青=接口缺失。点95仍为白=范围内、黑=范围外、橙=未知。外部界面直接显示分类，自动日志 `captures/holy-shield-*.log.txt` 记录每个物品、原始RGB、最终距离、全部盾击阻挡条件、成员血量和执行判断；每0.25秒采样，状态变化写入，稳定状态每5秒写一条。执行关闭时也记录，最小化后仍记录；日志不代表技能成功命中。

### 冷却选择与重新评估

群体大掉血、多人危急、普通群伤持续恶化，或单人危急且没有可用即时直接治疗时，可以考虑翅膀。翅膀不再要求鸣钟冷却，也不要求灌注确认不存在；灌注持续刷新或未知都不会独立阻止翅膀。当前可执行的危急直接治疗仍先于翅膀。连续采样确认普通群伤持续恶化时，翅膀优先于常规鸣钟，以覆盖后续压力；多人危急鸣钟仍可优先。

取消美德及大冷却之间的统一固定2秒阻挡。每次GCD／施法状态允许时，重新按血线、资源与技能可用性判断。美德铺垫后可以立即接直接治疗或符合伤情门槛的鸣钟；鸣钟不可用而血线仍严重时可以追加翅膀／光环掌握，恢复后保留冷却。每个冷却动作只对自身的重复按键请求限频0.5秒，不限制另一个可用技能；交替请求也不能绕过各自的节流。

连续伤情趋势仍由可靠且可比较的队伍快照判断：新增危急成员、任一成员血量下降至少8个百分点，或全体存活成员平均下降至少5个百分点可形成恶化信号。CooldownReviewSeconds沿用旧配置字段名，现在仅控制趋势采样周期，不是技能等待时间。上述百分比和采样周期均属于工具参数，不代表指南规定，也不代表确认了一两次有效治疗成功。

未知成员不能证明改善／恶化，但不会擦除每个按键的短暂重复请求节流。脱战、重新启动执行清理历史与节流，队伍可比较性变化或较长采样中断会清理伤情趋势。诊断关闭执行时的静态决策只显示单帧优先级，连续伤情与按键节流仅在实际Process链路运行。

光环掌握默认自动，当前用户已确认天赋含附带鸣钟效果。神圣界面提供“团本自动光环掌握”开关，默认勾选，点击立即保存；取消勾选后团本交给玩家手动释放，小队自动群疗不受该团本开关影响。仍要求AutoAuraMastery=true、AuraMasteryHasToll=true，团本另要求RaidAutoAuraMastery=true；未确认天赋时不推断附带鸣钟效果。普通严重压力遵守实际伤情、可用性与非紧急低圣能条件，需要时先用荣耀消耗。

至少两名成员低于Critical（默认20%）且群体采样可靠时，如果普通鸣钟不可用、光环掌握已学就绪且可用，优先紧急追加光环掌握，允许圣能溢出，不被当前目标的单体瞬发、自己治疗宏或选人确认持续抢占。仍要求玩家存活、战斗、未骑乘、施法结束、GCD就绪；同一光环掌握按键请求限频0.5秒。普通鸣钟可用时保留紧急鸣钟优先，单人危急仍优先直接抢救。没有附带鸣钟的光环掌握继续由玩家手动安排。

### 美德与常规治疗

美德要求群体治疗需求、技能就绪可用，并且当前确实有可执行的后续直接治疗：荣耀／免费荣耀、震击、灌注闪、神性之手瞬发圣光术，或站定可施放的闪现／符合条件的圣光术。危急目标先抢救。移动中没有瞬发或没有可执行后续治疗时，不空开美德。5圣能本身不再禁止后续有效治疗。当前可用性不能保证施放美德后仍有足够法力，后续每次施法继续重新检查。

地下城小队美德的普通触发线为至少两名存活成员低于85%，成员血量采样覆盖至少75%，有可治疗目标且有可执行后续治疗。美德可以对自己施放；当前选中自己或队友且满足条件时直接准备美德，不为了美德额外换目标。确需选人时按小队伤情选择自己或队友，并保留两次确认；普通自疗不抢占美德铺垫。自己或可治疗队友危急时先直接抢救。美德不启动固定2秒等待，也不被其他冷却的固定观察挡住，释放后下一次可施法机会继续治疗。后续治疗仅有普通圣光术时，目标还必须低于Major（默认60%）。美德按键为Shift+反斜杠（Shift+\），技能200025使用点29／39判断已学就绪与可用。

美德接收者与后续直接治疗接收者可以不同：自己满血而队友需要治疗时，只要有已确认可执行的后续治疗，仍可在自己身上铺美德，再按伤情选择治疗对象。确认当前目标就是玩家时，自己的治疗距离由单位身份证明，不依赖可能返回未知的友方距离查询。上述安排不代表工具已确认每人的道标状态。

小队默认先让美德和常规治疗工作，仍有需求再追加鸣钟／翅膀；紧急可叠加。团本允许更紧凑的美德与群疗衔接，并提供冷却手动保留选项。本轮仍不采集美德／翅膀生效状态或对象道标：尚未实现“确认窗口才优化灌注闪目标”与“真实翅膀覆盖”判断。可靠状态缺失时继续正常治疗，不等待窗口，也不把冷却计时当作Buff。

常规单体优先神圣意志免费荣耀、5圣能消耗；需要鸣钟时也先消耗3～4圣能。非危急的两充能震击仍优先灌注闪；一充能时先用灌注闪、神性之手瞬发圣光术，再震击和普通圣能消耗。灌注只判断有／无／未知，神性之手用独立Buff414273确认瞬发，施法后重新采样，不计固定次数。未知光环不能授权移动读条，但不会挡住已确认可用的其他治疗或翅膀。

普通读条圣光术仍要求治疗对象低于Major（默认60%）、确认无灌注、震击冷却、站定、法力达到HolyLightMana（默认30%），且技能已学、就绪并可用。神性之手瞬发圣光术不受这些额外条件限制，仍须有真实治疗需求及技能可用。普通闪现是站定治疗兜底，不要求灌注或震击状态已知。已学／冷却／可用未知只跳过依赖它的技能；施法／GCD未知仍暂停普通施法。

冷却与充能采集规则未改变：计时对象缺失时只以公开isEnabled／isActive确认冷却；缺字段、受限或报错保持未知。震击有充能数据时按实际剩余充能判断，正常nil可回退普通冷却，报错不能假定就绪。GetUnitSpeed仍直接交给原生StatusBar显示，普通读条依赖静止点10，确认瞬发的技能不依赖它。

### 可配置参数

关闭程序后修改运行目录 `profiles/holy.json` 的 `HolyThresholds`，再启动；旧文件缺少新增字段时采用默认值。比例使用0～1小数，观察时间使用秒。

| 字段 | 默认值 | 含义 |
|---|---|---|
| Critical | 0.20 | 危急直接抢救及多人危急例外 |
| TollLow / TollCritical | 0.80 / 0.60 | 小队鸣钟的3人／2人缺血线 |
| CooldownReviewSeconds | 2.0 | 伤情趋势采样周期（旧字段名），允许0.5～10秒；不阻挡美德或冷却释放 |
| AutoWings | true | 是否自动使用翅膀 |
| RaidAutoWings | true | 团本是否允许自动翅膀，false为团队安排保留 |
| AutoAuraMastery | true | 是否自动使用光环掌握 |
| AuraMasteryHasToll | false | 玩家确认当前天赋含光环掌握附带鸣钟；换天赋须同步修改 |
| RaidAutoAuraMastery | true | 团本是否允许自动光环掌握；界面开关控制，关闭交给玩家手动释放 |

团本翅膀需AutoWings和RaidAutoWings均为true；光环掌握需自动开关及天赋确认均为true，团本另需团本开关。未点附带鸣钟时保持手动。真实Buff观察仍留待后续单独配置，本轮无需重新取点。

## 点位、光环与首次启用

插件上行1～50为神圣专用字段；11保留食物标记采集，13复用原空槽判断神圣震击至少2充能，14／15／18为三个物品距离诊断槽；51～90共享成员血量，小队是自己、party1～4，团队是raid1～40。91／92是圣能≥3／5，93是灌注Buff有无，94是神性之手Buff有无，95是当前目标5码范围（仅物品），96确认神圣采集代码已加载；97／98是盾击已学且就绪／可用，99是当前目标审判距离，100确认简化灌注的新采集器已加载。新字段复用预留槽，坐标和总点数不变；旧物品诊断槽黑色会标记“旧采集器或未显示”。100未确认时不执行，避免把旧版94的灌注层数误认成瞬发圣光术Buff。治疗使用点22判断震击是否≥1充能，点13判断是否≥2充能以安排震击优先级；盾击不再依赖充能；两者由同一次充能采样交给原生阈值控件显示，不在Lua比较秘密数值。充能数据为nil时，治疗仍可使用冷却兜底，但点13为否，不能推断出2充能；接口报错／未知时点13为未知，不启用两充能震击优先分支。13复用原空槽，坐标和总点数不变。

灌注主动触发Buff ID是54149，53576是天赋被动，不能拿被动是否已学推断Buff存在。灌注和神性之手均只检查Buff是否存在，不读取层数。血量／充能／圣能秘密数值只交给原生显示控件。查询前先确认该光环接口可读；受限时显示橙色未知，不把受限查询的nil当成Buff缺失。神性之手使用414273；不再查询自律或圣疗的冷却与可用状态，原生18仅记录物品距离；30／40改为圣佑术498的已学且就绪／可用状态，不新增或移动点位。

外部窗口现在为三个固定点：101灌注Buff、104神性之手、105神圣意志。102美德治疗窗口与103复仇之怒BUFF已删除，其余编号不变。神圣意志点105的配置键是holy_purpose，必须单独取点／取色；不借用原生盾击距离点95，也不从已学天赋推断触发。接口可读时，灌注／神性之手自动使用接口点；受限时才使用配置的外部点。旧翅膀BUFF、美德窗口、自律点与旧2／3层点在加载时移除，剩余点按配置名称保留坐标和参考色。“灌注至少1层”点按同等的Buff有无保留，绝不拿旧层数点代替神性之手。旧配置仍可加载，未设置神圣意志时其状态为未知。外部显示编号105与选人动作编号105属于不同编号空间，不会把神圣意志当作party4。

美德施放还要求没有当前单体危急抢救，以及存在可执行的后续治疗。美德窗口外部点仍未恢复；不采集自己或他人的道标Buff，也不把冷却期或按键请求后的观察期当作治疗窗口。

外部点必须来自位置固定的状态指示区：条件为否时纯黑，为是时等于采集的非黑参考色，其他色未知。灌注、神性之手各用一个有无指示点，避开层数数字。移动的默认Buff列表、会变灰的冷却图标和数字抗锯齿边缘不能提供稳定的有无判断。没有可靠外部状态源时，跳过依赖灌注的瞬发闪现，以及依赖神性之手的瞬发圣光术，继续判断已确认可用的震击、荣耀及静止读条治疗；移动时不会把未知Buff当作瞬发。不能声称已经解决了游戏的光环访问限制。

用户当前客户端实测自律查询受限，因此按用户要求移除自律采集、取点与自动圣疗，改由玩家人工处理。

1. 更新HijiAddon，游戏 `/reload`，确认当前是神圣专精。
2. 按表配置动作宏和Shift+F1～F5。鸣钟0绑定自己宏，;绑定当前目标技能／宏。
3. 运行新编译的RotationUS。旧50点配置需重新定位100点：游戏 `/hiji locate on`，外部“定位测试”；通过后游戏 `/hiji locate off`，退出定位测试。
4. 执行保持关闭，检查点位：1／2／3、4／5、6／8、19／41、42～50、91～100，以及治疗／充能就绪。诊断文字会说明当前建议或等待原因。
5. 橙色光环字段需要可靠的固定外部点时，在三行中分别取点／取色并保存。神性之手和神圣意志各需单独配置；验证灌注有／无、开翅膀后两次瞬发圣光术前后Buff的存在／消失，以及神圣意志触发后低圣能时的免费治疗，再验证换目标、进出距离，之后开启执行。
